# Reflection

## Decisions
One of the biggest decisions I made was turning the site from a single-page layout into a multi-page website. I did this because the project topic had enough content to support separate pages, and the navigation felt cleaner when each tab had its own space. I also decided to keep the design consistent across every page by using the same CSS file and the same JavaScript file. That choice made the site feel more professional and saved me from repeating code in every HTML file.

Another important decision was keeping the theme toggle and habit tracker from the original version. I could have simplified the project by removing them, but I felt they added something useful to the site. The theme toggle made the site feel more modern, and the tracker gave the page an interactive feature instead of making it only informational. I also chose to use clear, easy-to-read content rather than trying to make the site look crowded or overly complicated.

## What worked
What worked best was the organization. Once I separated the content into different pages, it became easier to think about what each part of the site should do. The homepage introduces the topic, the impact page explains the problem, the habits page gives solutions, the tracker page makes the site interactive, and the facts page explains the project itself. That structure made the site easier to build and easier to understand.

I am also satisfied with the design consistency. The same color scheme, spacing, and card layout across the site makes it feel connected. The theme switch worked out well because it gives users a choice between auto, light, and dark mode without changing the overall layout. The habit tracker also worked better than I expected because it gave the site a simple but meaningful feature that matches the topic.

## What I would do differently
If I started over, I would plan the page structure earlier instead of building the whole site as one page first. That would have saved time when I decided to split the tabs into separate pages. I would also separate the shared code into reusable parts sooner, especially the navigation and theme logic, so I would not have had to copy and adjust as much code.

I would probably spend more time on the content before writing the final layout. A few of the pages could be stronger if the text were shorter and more focused. I might also add real usage data or visuals to the tracker page instead of using a fixed example value. That would make the project feel more realistic and would better match the idea of tracking habits over time.

## What I learned
I learned that web design is easier when the content structure is clear before the coding starts. Building the site taught me that a good project is not just about making things look nice; it is also about organizing information in a way that makes sense for the user. I also learned that small features like navigation, theme switching, and a simple form can make a site feel much more complete.

I learned more about how HTML, CSS, and JavaScript work together as separate jobs in one project. HTML gave the pages structure, CSS controlled the layout and visual style, and JavaScript handled the interactive parts. I also learned that I work better when I break a project into smaller pieces instead of trying to solve everything at once. Overall, this project helped me understand both the technical side of building for the web and my own process for staying organized while I build.
